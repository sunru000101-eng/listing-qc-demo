质检台

房源提交后先过一遍机检，输出风险分与逐条命中原文，再给一版可直接替换的合规文案。左侧可选样本库里的房源，也可以直接改文案实时看分数变化。

模型层：为什么规则层不够，以及我打算怎么补
规则层抓的是字面违规。样本库里我故意埋了 3 条语义类违规（不含任何违禁词，但人工一眼判违规），规则层必然漏——见评测台的漏检清单。 这类只能上模型。但模型不该跑全量：规则层已判 reject 的直接打回，不必再花 token，模型层只跑规则层放行的部分。 
【模型层 Prompt v0.1】
你是租房平台的房源合规审核员。只判断下面这条房源描述是否存在
"不含违禁关键词、但实质违规"的表述，输出 JSON。

需要识别的实质违规（字面绕开也算）：
1. 教育承诺 —— 不写"学区房"，但暗示与某学校的入学关联
2. 身份/地域筛选 —— 不写"不租某某人"，但设置隐性人群门槛
3. 投资诱导 —— 不写"升值"，但暗示租金或房价会涨
4. 夸大承诺 —— 对安全、隔音、通勤时长等给出无法兑现的断言

输出：{"hit":bool,"cat":"","evidence":"原文片段","reason":"一句话","conf":0-1}
无法确定时 hit=false 并把 conf 压低，交人工——宁可漏，不可误杀房东。

上线结论

Demo 做到这里为止，剩下的是一个产品经理该给出的东西：这版能不能上、上到哪、怎么灰度、下一步补什么。

建议

不建议现在做的事（同样重要）

  • 不做全自动打回。误杀一个真房东的成本远高于放过一条脏房源——前者直接掉供给，后者还有租客举报作为第二道网。所以 reject 档的定位是"打回让房东改"，不是"封禁"。
  • 不做图片 AI 生成美化。技术上我做得了（前司干过视频转绘和物体擦除），但房源图美化会直接放大"图文不符"投诉，属于用技术制造业务问题。要做也只做去水印、亮度矫正这类不改变房屋事实的处理。
  • 模型层不跑全量。规则层已判 reject 的不必再花 token，模型层只覆盖规则层放行的部分，成本降到约四成。

如果拿到你们真实数据，我第一周会这么排

  1. 把现有审核规则和拒绝理由捞出来先不写代码。看人工审核最近 N 条的驳回理由分布，找出占比最高的三类——现在这 5 个维度是我拍的，真实分布大概率不长这样。
  2. 建真实评测集从线上抽 300 条（按驳回理由分层抽样），拉一位审核同学一起标注。评测集的质量决定后面所有结论的可信度，这一步不能省。
  3. 规则层对齐真实规则把 demo 里的词表和冲突规则换成平台实际的审核标准，在 300 条上跑基线。
  4. 接模型层，只跑规则层放行的部分用第 2 天的评测集测漏检回收率和误杀增量，算清单条成本。
  5. 定阈值与灰度方案拿真实指标重跑今天这张阈值表，产出"自动过 / 转人工 / 打回"三档的分界，并明确灰度范围（建议先新房东、不动老房东）。
  6. 和审核团队过一轮让审核同学试用半天，收集他们不认可的判定——审核员是这个产品的真实用户，他们不用，指标再好也没用。
  7. 出上线结论一页纸：上 / 不上 / 上到哪，附带回滚条件。
数据说明：本 demo 的 40 条房源为合成样本，人工标注（ground truth）由我本人完成，未使用任何平台真实数据。
规则层为浏览器端实时计算，评测台所有指标随阈值实时重算，非预置结果。模型层尚未接入，Prompt 设计见「质检台 → 模型层」。
